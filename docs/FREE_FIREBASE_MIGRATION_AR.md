# ترحيل English Hub مع Firebase المجاني

## سياسة التكلفة

هذا الإصدار لا يعتمد على Cloud Functions أو Cloud Run أو Phone Authentication أو Extensions أو أي خدمة تحتاج Blaze كجزء أساسي من التشغيل. يبقى الاستخدام ضمن خدمات Firebase المتاحة في Spark، مع الالتزام بحدود التخزين والقراءات والكتابات والنقل المنشورة في صفحة Firebase Pricing.

## ما تم تطبيقه في الكود

أصبحت الواجبات الجديدة والمحاولات الجديدة تسجل `stageId`. لوحة التحكم لا تستمع إلى كل المحاولات، بل تستعلم عن محاولات القسم الحالي فقط. شاشة الطالب تستعلم عن أسئلة القسم الحالي بدل تحميل بنك الأسئلة كاملًا. تمت إضافة توافق مع البيانات القديمة التي لا تحتوي `stageId` حتى لا تتوقف أثناء الترحيل.

## قواعد V2

الملفان `firestore.v2.rules` و`storage.v2.rules` هما قواعد مقترحة للترحيل، وليسا بديلًا يتم نشره مباشرة. يجب أولًا إضافة `workspaceId` وعضوية Workspace إلى الوثائق، ثم تحديث جميع استعلامات الواجهة، ثم اختبار القواعد على Emulator أو مشروع اختبار منفصل.

## خطة الترحيل الآمنة

1. احتفظ بنسخة تصدير من Firestore قبل أي تغيير.
2. أضف الحقول الجديدة إلى الوثائق الجديدة فقط.
3. شغّل تقريرًا للوثائق القديمة التي لا تحتوي `stageId` أو `workspaceId`.
4. حدّث الاستعلامات تدريجيًا، مع إبقاء fallback للبيانات القديمة.
5. اختبر القراءة والإضافة والتعديل والحذف لكل دور: مدير، مدرس، طالب، مستخدم معطّل.
6. انشر قواعد V2 بعد نجاح الاختبارات، وليس قبلها.
7. راقب استهلاك Firestore وStorage، وحدد حجم الملفات قبل الرفع.

## قيد أمني مهم

التصحيح الآلي الحالي يعمل في المتصفح، ولذلك يمكن للمستخدم المتمرس رؤية مفاتيح الإجابة في بيانات الصفحة. منع ذلك نهائيًا يحتاج مسارًا موثوقًا على الخادم. وبما أن هذا المشروع يجب أن يبقى مجانيًا، تم عدم إدخال Cloud Functions كاعتماد إجباري. الخيار المجاني الحالي هو استخدام التصحيح الآلي للتدريب غير الرسمي، أو تحويل الاختبارات النهائية إلى مراجعة يدوية من المدرس.
